# LEAD() — заглядываем в будущие строки

**LEAD()** — это оконная функция, которая позволяет получить значение из следующей строки в том же наборе данных без использования JOIN. Её «зеркальное отражение» — LAG(), которая смотрит на предыдущую строку.

## Синтаксис

```sql
LEAD(выражение [, смещение [, значение_по_умолчанию]]) 
    OVER ([PARTITION BY ...] ORDER BY ...)
```


| Параметр                | Описание                                                                  | По умолчанию  |
| :---                    | :---                                                                      |    :---:      |
| `выражение`             | Столбец или формула, значение которого нужно взять из следующей строки    | -             |
| `смещение`              | На сколько строк вперёд заглянуть                                         | 1             |
| `значение_по_умолчанию` | Что вернуть, если следующей строки нет (конец окна)                       | NULL          |




### 📊 Простой пример
Допустим, есть таблица ежедневных продаж:
|    date     | revenue|
|   :---:     |  :---: |
|  2024-01-01 |  1000  |
|  2024-01-02 |  1200  |
|  2024-01-03 |  1100  |
|  2024-01-04 |  1500  |


**Запрос**: посмотреть выручку следующего дня и разницу с текущим.


```sql
SELECT 
    date,
    revenue,
    LEAD(revenue) OVER (ORDER BY date) AS next_day_revenue,
    LEAD(revenue) OVER (ORDER BY date) - revenue AS daily_change
FROM sales;
```

| date       | revenue | next_day_revenue | daily_change |
|------------|---------|------------------|--------------|
| 2024-01-01 | 1000    | 1200             | +200         |
| 2024-01-02 | 1200    | 1100             | -100         |
| 2024-01-03 | 1100    | 1500             | +400         |
| 2024-01-04 | 1500    | NULL             | NULL         |


Для последней строки `LEAD()` вернул `NULL`, так как «следующего дня» в выборке нет. Арифметика с `NULL` тоже даёт `NULL`.
Если нужно заменить `NULL` на `0`, используем `COALESCE`:

```sql
SELECT
    date,
    revenue,
    COALESCE(LEAD(revenue) OVER (ORDER BY date), 0) AS next_day_revenue,
    COALESCE(LEAD(revenue) OVER (ORDER BY date), 0) - revenue AS daily_change
FROM sales;
```

**Применение**

| Задача | Как решается через `LEAD()` |
|---|---|
| Рост/падение показателей | `LEAD(value) - value` или `(LEAD(value) - value) / value * 100` |
| Время до следующего события | `LEAD(event_time) OVER (...) - event_time` |
| Поиск следующего шага в воронке | `LEAD(step_name) OVER (PARTITION BY user_id ORDER BY created_at)` |
| Сравнение с будущим периодом | Финансовые отчёты, прогнозирование, анализ сезонности |

**Важные нюансы**

- `ORDER BY` обязателен внутри `OVER()`. Без него PostgreSQL не знает, какая строка считается «следующей».
- `PARTITION BY` работает как обычно: `LEAD()` смотрит вперёд только внутри своей группы.
- Можно заглядывать дальше, чем на 1 строку, указав второй аргумент:
```sql
-- Смотрим на 2 строки вперёд
LEAD(revenue, 2) OVER (ORDER BY date)
```

**Не путать с `LAG()`:**
- `LAG()` → предыдущая строка (вчера, прошлый месяц, прошлый клик)
- `LEAD()` → следующая строка (завтра, следующий месяц, следующий клик)

**Быстрая шпаргалка**

```sql
-- Значение из следующей строки
LEAD(col) OVER (ORDER BY date)

-- Значение через N строк вперёд
LEAD(col, 3) OVER (PARTITION BY user_id ORDER BY created_at)

-- Заменить NULL, если следующей строки нет
LEAD(col, 1, 'Нет данных') OVER (ORDER BY date)

-- Разница с будущим значением
LEAD(amount) OVER (ORDER BY date) - amount AS expected_change
```
