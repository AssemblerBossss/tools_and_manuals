# Генерилка сообщений для реббита

Генерирует `COUNT` сообщений и складывает в реббит  

Если мы указываем и `QUEUE` и `EXCHANGE` - сервис будет автоматически биндить с указанным роутинг кеем (ВТЧ пустым).  
Если хотим складывать в очередь - заполняем только переменную `QUEUE`.  

`PASSIVE` - если сделать false - будет декларировать указанные очереди, эксчейнджи если они не существуют. Ежели `PASSIVE` true - будет падать если не найдет нужных очередей/ексчейнджей.  

## Описание специфических параметров

| Название | Описание | По умолчанию |
|------------|------------|------------|
| `COUNT` | Количество генерируемых сообщений  | **100000** |
| `TO_USERNAME` | Имя пользователя реббит  | **rmuser** |
| `TO_PASSWORD` | Пароль пользователя реббит  | **rmpassword** |
| `TO_HOSTNAME` | Адрес реббита в который необходимо перекладывать сообщения  | **rabbitmq** |
| `TO_PORT` | Порт реббита  | **5672** |
| `TO_QUEUE` | Очередь в которую необходимо перекладывать сообщения (не обязательно, можно через эксчйендж)  | **gen** |
| `TO_EXCHANGE` | Ексчейндж в который необходимо перекладывать сообщения (желательно, но вместо нее можно указать очередь `TO_QUEUE`)  | **nil** |
| `TO_ROUTINGKEY` | Роутинг кей с которым будут перекладываться сообщения (не обязательно)  | **nil** |
| `TO_PASSIVE` | Пассивный режим - проверяет наличие очереди/ексчейнджа и падает если не находит  | **true** |
| `APP_DEBUG` | Режим отладки  | **false** |
| `JOB_MODE` | Режим джобы - умирает после выполнения. Если не включено - после выполнения зависает в while-true  | **false** |
| `SLEEP` | Эмуляция задержек между отправками сообщений, в милисекундах  | **0** |
| `REPORT` | Частота отчетности в логах, каждые `REPORT` сообщений  | **10000** |
