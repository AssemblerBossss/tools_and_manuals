# 🚀 Туториал по транзакциям в Redis

Redis — это in-memory key-value хранилище, которое поддерживает **транзакции** для выполнения нескольких команд атомарно.  

---

## 📖 Теория

### Что такое транзакция в Redis?

- Транзакция в Redis — это **последовательность команд**, которые выполняются **атомарно**.  
- Для работы используется три ключевых команды:
  - `MULTI` — начинает транзакцию.
  - `EXEC` — выполняет все команды в транзакции.
  - `DISCARD` — отменяет транзакцию.
- Redis не поддерживает полный **ACID** как реляционные базы, но гарантирует:
  - Все команды из `MULTI`/`EXEC` выполняются последовательно без прерываний другими клиентами.
  - Нет частичного выполнения: либо все команды выполняются, либо транзакция отменяется.

### Важный нюанс

- Проверка ошибок в транзакции работает по принципу:
  - Если ошибка синтаксическая (например, неправильная команда), Redis отменяет транзакцию.
  - Если ошибка возникает во время выполнения (например, `INCR` на строке), остальные команды всё равно выполнятся.

---

## 🛠 Практика

### 🔹 Простейшая транзакция

```bash
127.0.0.1:6379> MULTI
OK
127.0.0.1:6379> SET user:1 "Alice"
QUEUED
127.0.0.1:6379> INCR visits
QUEUED
127.0.0.1:6379> EXEC
1) OK
2) (integer) 1
```

- Здесь:
  - Мы создали ключ `user:1` со значением `Alice`.
  - Увеличили счётчик `visits` на 1.
  - Все команды выполнились атомарно.

## Отмена транзакции

```bash
127.0.0.1:6379> MULTI
OK
127.0.0.1:6379> SET user:2 "Bob"
QUEUED
127.0.0.1:6379> DISCARD
OK
127.0.0.1:6379> GET user:2
(nil)
```

Здесь транзакция была отменена, и ключ `user:2` не создался.

## Ошибки в транзакциях

```bash
127.0.0.1:6379> MULTI
OK
127.0.0.1:6379> SET number "not_a_number"
QUEUED
127.0.0.1:6379> INCR number
QUEUED
127.0.0.1:6379> EXEC
1) OK
2) (error) ERR value is not an integer or out of range
```

Первая команда выполнилась `(SET)`, вторая упала с ошибкой, но Redis не отменил транзакцию полностью.

## 🔒 WATCH: оптимистическая блокировка

Redis также поддерживает механизм оптимистической блокировки через команду `WATCH`.
Она позволяет отменить транзакцию, если ключ изменился другим клиентом до выполнения `EXEC`.

Пример:

```bash
# Клиент 1
127.0.0.1:6379> WATCH balance
OK
127.0.0.1:6379> MULTI
OK
127.0.0.1:6379> DECRBY balance 10
QUEUED
127.0.0.1:6379> EXEC
1) (integer) 90
```

## ✅ Выводы

Redis транзакции обеспечивают атомарность выполнения нескольких команд.

Они не откатывают изменения при ошибках выполнения, поэтому важно проектировать команды осторожно.

Для конкурентного доступа стоит использовать `WATCH` и `MULTI` как механизм блокировок.
