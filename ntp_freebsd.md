## Введение

**NTP (Network Time Protocol)** — протокол для синхронизации времени между узлами сети. FreeBSD поставляется с `ntpd` в базовой системе, поэтому дополнительная установка в большинстве случаев не требуется.

---

## Установка NTP

### Вариант 1 — базовый `ntpd` (уже входит в систему)

Убедитесь, что бинарник присутствует:

```sh
which ntpd
# /usr/sbin/ntpd
```

### Вариант 2 — установка из портов (openntpd или chrony)

```sh
# OpenNTPD
pkg install openntpd

# Chrony (рекомендуется для виртуальных машин)
pkg install chrony
```

> Далее в инструкции описывается настройка стандартного **ntpd** из базовой системы.

## Конфигурация ntpd

Основной файл конфигурации: `/etc/ntp.conf`

```sh
cp /etc/ntp.conf /etc/ntp.conf.bak   # сделать резервную копию
vi /etc/ntp.conf
```

### Минимальная конфигурация

```
# /etc/ntp.conf

# --- Вышестоящие серверы (stratum 1/2) ---
pool 0.ru.pool.ntp.org iburst
pool 1.ru.pool.ntp.org iburst
pool 2.ru.pool.ntp.org iburst
pool 3.ru.pool.ntp.org iburst

# --- Файл для сохранения смещения частоты ---
driftfile /var/db/ntpd.drift

# --- Логирование ---
logfile /var/log/ntpd.log

# --- Запрет доступа по умолчанию ---
restrict default kod nomodify notrap nopeer noquery

# --- Разрешить localhost ---
restrict 127.0.0.1
restrict ::1

# --- Разрешить клиентам из локальной сети синхронизироваться ---
# Замените на свою подсеть
restrict 192.168.1.0 mask 255.255.255.0 nomodify notrap
```

### Описание ключевых директив

| Директива | Описание |
|---|---|
| `pool` | Использовать пул серверов (предпочтительнее `server`) |
| `iburst` | Ускоренная первичная синхронизация |
| `driftfile` | Файл для хранения дрейфа частоты |
| `restrict default` | Политика доступа по умолчанию |
| `kod` | Отправлять «Kiss-of-Death» пакет при превышении лимита |
| `nomodify` | Запретить изменение конфигурации ntpd удалённо |
| `notrap` | Отключить режим ловушки |
| `nopeer` | Запретить создание peer-ассоциаций |
| `noquery` | Запретить запросы ntpq/ntpdc |

## Запуск и автозапуск службы

### Включить ntpd при загрузке системы

Добавьте в `/etc/rc.conf`:

```sh
sysrc ntpd_enable="YES"
sysrc ntpd_sync_on_start="YES"   # однократная синхронизация при старте
```

Или вручную отредактируйте `/etc/rc.conf`:

```
ntpd_enable="YES"
ntpd_sync_on_start="YES"
```

### Управление службой

```sh
# Запустить
service ntpd start

# Остановить
service ntpd stop

# Перезапустить
service ntpd restart

# Проверить статус
service ntpd status
```

## Настройка firewall

Если используется **pf** или **ipfw**, необходимо разрешить UDP-порт **123**.

### pf (`/etc/pf.conf`)

```
# Разрешить входящий NTP от клиентов
pass in on em0 proto udp from 192.168.1.0/24 to any port 123
```

### ipfw

```sh
ipfw add allow udp from 192.168.1.0/24 to me 123
```

После изменения правил перезагрузите firewall:

```sh
service pf reload   # для pf
```

## Проверка работы

### Просмотр пиров

```sh
ntpq -p
```

Пример вывода:

```
     remote           refid      st t when poll reach   delay   offset  jitter
==============================================================================
*ntp1.example.com  .GPS.            1 u   42   64  377    1.234   -0.512   0.215
+ntp2.example.com  .PPS.            1 u   38   64  377    2.100    0.321   0.143
```

Значение символов в столбце `remote`:

| Символ | Значение |
|---|---|
| `*` | Основной (выбранный) источник |
| `+` | Кандидат (используется при необходимости) |
| `-` | Исключён из выборки |
| `x` | Недостоверный источник |

### Проверка синхронизации

```sh
ntpq -c sysinfo
ntpdate -q pool.ntp.org    # тестовый запрос без изменения времени
```

### Просмотр логов

```sh
tail -f /var/log/ntpd.log
```

## Дополнительные параметры

### Использование локального сервера как fallback

Если внешние серверы недоступны, можно настроить локальные часы как источник последнего резерва:

```
server 127.127.1.0
fudge  127.127.1.0 stratum 10
```

### Ограничение числа клиентов

```
# Разрешить не более 5 клиентов из подсети
restrict 192.168.1.0 mask 255.255.255.0 nomodify notrap limited
tos minclock 3 maxclock 6
```

### Включение мониторинга (ntpq)

```
# Разрешить ntpq-запросы только с localhost
restrict 127.0.0.1 nomodify notrap
```

## Итог

После выполнения всех шагов ваш FreeBSD-сервер будет:

- синхронизироваться со временем из пула `pool.ntp.org`
- принимать NTP-запросы от клиентов в локальной сети
- автоматически стартовать после перезагрузки

Клиенты в сети могут использовать IP вашего сервера как NTP-источник:

```sh
# Пример для другой FreeBSD-машины
sysrc ntpd_enable="YES"
echo "server 192.168.1.1 iburst" >> /etc/ntp.conf
service ntpd restart
```
